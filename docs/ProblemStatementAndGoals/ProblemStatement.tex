\subsection{Inputs and Outputs}

\subsection{Inputs}
\begin{enumerate}
    \item Taps on the screen: Mobile app users will need to click the screen to complete actions in the application.
    \item Activity Information: Connection to a pedometer, heart rate monitor, etc. 
        Many of these technologies can be provided by the device running the application.
    \item User Personal information: Information like height, weight, health conditions, current fitness level and current understanding of finance will be entered to enhance the experience.
\end{enumerate}
\subsection{Outputs}
\begin{enumerate}
    \item Virtual currency: Users will be able to collect virtual currency by completing fitness tasks and smart investing. Users will then be able to spend the currency as they choose. 
    \item Real world rewards: virtual currency can be traded for real world incentives (i.e. free trials for paid services).
\end{enumerate}

\subsection{Stakeholders}
\begin{itemize}
    \item Users: Young and older adults who would like to learn more about personal fitness and/or financial responsibility.
    \item Project Supervisor: provided initial project description and will continue to provide insights throughout the project.
    \item Banks: users who learn more about financials will be more inclined to involve themselves  in their personal finances.
    \item Gyms/Training Facilities: users will be able to learn more about fitness and utilizing gyms/training facilities provides a space for this purpose.
\end{itemize}

\subsection{Environment}

Users will be able to use the application from their smart devices. 
The project will need to be supported by the current hardware and software systems in place that run these smart devices. 
The application will be developed to be supported by the android operating system and hardware. 
The distribution of the application will be handled by the respective application stores of the smart devices. 
Integration with other devices/products that can read fitness data will need to be supported by the smart device. 
The integration must be supported by an SDK, API, or other package developed by the manufacturer of the device/product that will allow data retrieval.
\section{Goals}

\begin{enumerate}
    \item \textbf{Educate Users on the Power of Compounding}: Compounding is the process by which financial earnings from investments (dividends and capital gains) are re-invested, accelerating the growth of the investments.
    It is the most important concept to grasp in order to become financially literate.
    Fitness is also a compounding habit, where early action can lead to long-term positive outcomes on one's health.
    The application will educate its users on compounding by rewarding positive fitness habits, as well as healthy financial choices.
    This can be measured by the number of users who:
    \begin{enumerate}
        \item Report a positive learning experience through user surveys
        \item Show consistent financial growth (dollars gained as a percentage)
        \item Show consistent workout results through use of app
    \end{enumerate}
    \item \textbf{Integrate with Already Existing Fitness Technologies}: To best track users' fitness activities, the application will integrate with technologies already in use by users.
    The exact technologies will be determined during the \textit{design thinking} exercise.
    This can be measured by the number of users who are able to connect at least one of their fitness devices to the application.
    \item \textbf{Provide a Simple and Delightful User Experience}: The design of the application should be friendly to all users.
    It should be straightforward, and navigable, with all key components being reachable through minimal clicks.
    This can be measured through user verification and validation, as well as by following accessibility frameworks.
    \item \textbf{Drive Long-Term User Engagement}: Compounding only pays off with sustained participation over time.
    A single workout or investment will not make a difference, but one a week for years will.
    The application must encourage users to remain active on the platform in the long term, in order to reap the benefits of compounding.
    This can be measured through the percentage of users who remain active over 30, 60 and 90 days from sign-up.
\end{enumerate}

\section{Stretch Goals}

\begin{enumerate}
    \item \textbf{Design Unique Interactions for Users with Varying Knowledge Levels}: Create different interactions for users who have more knowledge in finance versus more knowledge in fitness.
    These unique interactions allow for a more customized learning experience for the users.
    \item \textbf{Leverage Generative AI in Investments}: Utilize LLMs as a source of learning for the users.
    The LLMs will be able to provide lessons on both the fitness side and finance side.
    Workout and financial advice may also be possible, though regulations will need to be checked.
    \item \textbf{Incorporate Real Life Incentives}: Partner with companies, brands, and organizations to create in real life (IRL) incentives for the users.
    These partnerships will drive even more long term engagement with the application as well as further incentivizing proper compounding habits.
\end{enumerate}
The stretch goals listed above are currently out of scope due to time constraints, but may be considered later in the development cycle.
